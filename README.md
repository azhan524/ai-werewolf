# 🐺 AI 狼人杀（标准 12 人局）

> An open-source desktop app for **AI Werewolf**: you act as the human host (God) and 12 AI models
> play a full 12-player game of Werewolf in isolated channels. Windows · WebView2 · Node.js · MIT.

一个**桌面程序**：人类当主持人（上帝），只负责点按钮推进流程，**不参与游戏**；
多个 AI 扮演 12 名玩家，在彼此**隔离的频道**里完成一整局狼人杀。

- 左侧：5 个**持久频道**（公共 / 狼人 / 预言家 / 女巫 / 守卫），点击切换查看
- 中间：频道聊天记录，标注玩家编号、昵称、身份（主持人视角可见全部身份）
- 右侧：座位面板，显示存活状态、身份、私有状态（药水/枪/守护记录）、绑定的 AI 模型，**下拉框直接换模型**
- 顶部：主持人控制栏，按钮随游戏阶段自动切换
- 右上角：🔄 开新一局 ／ 🔎 隔离自检 ／ ⏹ 停止

### 身份分配方式：默认随机，也可手动指定

「开新一局」里有两种模式：

| 模式 | 说明 |
| --- | --- |
| 🎲 **随机分配（默认）** | 程序把所选板子的身份**洗牌后随机发给每个座位**。AI 玩家事先都不知道谁是什么身份，跟真人局一样 |
| ✍️ **手动指定** | **逐个座位**选身份（还能顺手给座位起个名），程序**不洗牌**：你给"1号"选的第一个身份就是他。适合剧本局、复盘、或者特意安排"让哪个模型当狼" |

- 手动模式同样有合法性校验（至少 4 人、最多 18 人、狼人 ≥1 且不过半），不合规会被拒绝
- **开完局之后**也能随时在右侧座位面板点「编辑」单独改某个座位的身份或昵称 —— 同样是改一个字段，频道和历史不受影响
- 顶部座位面板标题会显示当前这局是「随机分配」还是「手动分配」

### 已实现的规则细节

- **屠边胜负**：狼人杀光**所有神职** 或 **所有平民** 即获胜；好人杀光狼人获胜（可切换为屠城）
- **同守同救**：守卫守的人和女巫解药救的人是同一个 → 该玩家**死亡**（可关闭）
- **守卫不能连守**：程序不允许连续两晚守同一个人（AI 说了也会被拦下）
- **女巫用药限制**：同一晚只能用一瓶药；自救规则可选「仅首夜 / 从不 / 总是」
- **猎人 / 狼王开枪**：被狼刀、被票出局可开枪；**被女巫毒死时枪失效**
- **白痴翻牌**：被投票放逐时翻牌不死、失去投票权（计票时自动跳过无投票权的人），仍可发言
- **白狼王自爆**：白天自爆 → 自己出局 + 带走一人 + 直接进入黑夜
- **夜间流程**：守卫 → 狼人 → 预言家 → 女巫 → 结算
- 死亡只公布"谁死了"，不公布身份；被投票放逐者**公布身份**

## 二、消息隔离是怎么实现的（重点）

### 1. 权限矩阵是唯一真相

`lib/channels.js` 里每个身份只声明自己能看的频道：

| 身份 | 可视频道 |
| --- | --- |
| 狼人 / 狼王 / 白狼王 | 公共 + 狼人 |
| 预言家 | 公共 + 预言家 |
| 女巫 | 公共 + 女巫 |
| 守卫 | 公共 + 守卫 |
| 猎人 / 白痴 / 平民 | 仅公共 |

```js
export function allowedChannels(role) { … }   // ★ 全程序唯一的权限查询入口
export function canRead(role, channelId) { … }
```

未定义的身份一律按平民处理（最小权限原则）。

### 2. 只有一处能拼 prompt

`buildPrompt()` 是整个程序里**唯一**把频道正文写进提示词的地方，它：

1. 校验这次发言的频道是否在该座位权限内，越权直接抛 `FORBIDDEN_CHANNEL`；
2. 遍历频道时**跳过所有无权频道**（`buildTranscript()`），一个字都不带进去；
3. 转录里**不带任何身份标签**——格式是 `[公共频道] 3号·老K：……`，AI 无法从格式里读出别人身份；
4. 组装成 `system(我是几号/什么身份/技能/规则) + user(我可视频道的转录 + 当前任务)`。狼队友名单只会写进狼人的 system 提示里。

### 3. 组装完还要反向自检（第二道防线）

`assertNoLeak()` 拿着**成品 prompt** 去所有无权频道里逐条比对，只要发现无权频道的正文片段出现在里面，就抛 `MESSAGE_LEAK` 并**中止这次模型调用**（宁可这一轮不发言，也绝不泄漏）。

> 误报处理：如果同一句话也合法地出现在该座位**有权**看到的频道里（比如主持人把同一句公告发到多个频道），不算泄漏。

### 4. UI 上可随时验证（第三道防线）

顶部 **🔎 隔离自检** 会对全部 12 个座位跑一遍：组装真实 prompt → 正向校验（有权频道要带进来）→ 反向校验（无权频道不能出现）→ `assertNoLeak` 双保险，并给出报告。另外每条 AI 消息下面都会标出**这次实际带入了哪些频道**（如 `可见：公共频道+狼人频道`）。

### 5. 观众视角

右上角 👁 切换「观众视角」：只返回公共频道、不返回任何身份、并剥掉能反推身份的字段（如 `includedChannels`——它等于告诉观众"这人看得到狼人频道"）。适合投屏。

## 三、发言秩序（不会抢麦、也不会漏麦）

多 AI 群里最容易出现的混乱是"轮到 3 号，4 号突然抢话"。这个程序从四个层面堵住了：

**1. 单发锁 —— 不可能同时有两个人说话**
`Orchestrator` 内部只有一个 `run` 槽位，`speakOnce()` 先用 `_guard()` 抢占，占不到就直接抛错。
`speakMany()`（狼人依次发言、全体投票）也是**逐个 await**，不是并发。所以频道里任何时刻最多只有一条在流式生成。

**2. 队列点名 —— 没被点到的人根本不会被调用**
白天发言由 `speakQueue()` 维护：`startDay()` 按存活玩家生成发言顺序（每天整体轮换一位，避免永远 1 号先开口），
`nextSpeaker()` 依次推进。**只有队列当前那一位才会被调用模型**，其他座位这一轮压根不参与，不存在"自己抢麦"的通道。
队列会自动跳过已出局的人，并正确处理"发言中途有人开枪死亡"。

**3. 麦克风占用保护 —— 抢麦/切阶段的操作一律拒绝**
`server.js` 里凡是**调用模型**或**切换阶段**的动作（天黑/守卫/狼人/验人/女巫/天亮/下一位发言/全体发言/开始投票/全体投票/计票/开枪/自爆/单独发言），
在有人正在生成时都会返回 `409` 并提示：

```
409  10号 模型4还在发言，发言队列已暂停。请等 TA 说完，或点「停止」再继续。
```

> 这条修复顺带解决了一个真 bug：以前 `nextSpeaker` 是"先推进队列、再调用模型"，
> 如果上一次还在生成，模型调用被锁挡下 → **那一位就被永久跳过了**。现在占用检查发生在任何状态改动之前。

**4. 提示词里写明秩序 + 界面显示队列**
每次发言的 task 都会告诉 AI：`你是本轮第 3 位发言（本轮共 10 位存活玩家依次发言）`、
`★ 现在全场只有你一个人在说话，其他人都还没轮到。不要说别人的台词、不要写「X号：…」、也不要假装别人已经回应了你。`
系统提示里也有一条同样的铁律。界面上控制栏下方有一条**发言队列**，把"谁已经说过 ✓ / 现在轮到谁（高亮）/ 谁还在等 / 谁已出局（划掉）"直接摆出来。

对应的自动化断言（全部通过）：

```
✅ 同时点两次「下一位发言」只有一个人能说话（另一次 409）
✅ 被拒绝的那次没有让任何人多说话/被跳过（只消耗一个发言名额）
✅ 队列记录的已发言人数 = 实际发言条数
✅ 自动发言进行中，点「开始投票」/「下一位发言」都会被挡住
✅ 每位存活玩家都发言了一次（不重不漏）
✅ 白天发言的提示词写明「现在只有你在说话」与「你是本轮第 N 位发言」
```

## 四、死亡流程：遗言 · 警徽 · 开枪

**核心原则：出局的人不能再随便发言，只有三个合法通道 —— 遗言、开枪、移交警徽。**

所有死亡都走同一个入口 `killSeat()`，它会统一记录死因/天数、把需要遗言的人排进队列、并检查死者是不是警长（是则登记待移交警徽）。

### 遗言（默认按标准规则）

| 死因 | 默认是否有遗言 | 说明 |
| --- | --- | --- |
| 首夜被狼刀 / 同守同救 | ✅ 有 | 标准规则：第一晚死亡有遗言 |
| 第二夜及以后被狼刀 | ❌ 无 | 标准规则 |
| 白天被投票放逐 | ✅ 有 | 标准规则 |
| 被女巫毒杀 | ❌ 无 | 毒杀是无声的（同时猎人的枪也会失效） |
| 被猎人/狼王开枪带走 | ❌ 无 | 标准规则 |
| 被白狼王自爆带走 | ❌ 无 | — |

每一条都可以在 ⚙ 对局设置里单独勾选。

**白天的推进顺序由状态机统一决定**（主持人不用记流程，控制栏会自己变）：

```
天亮公布死讯 → 遗言 → 警徽移交 → 开枪 → 上警 → 警长竞选投票 → 正式发言 → 放逐投票 → 进入下一夜
```

遗言与开枪的先后也可以配（默认：先遗言、再开枪）。

### 已出局玩家的发言边界

- `speakOnce()` 默认拒绝已出局的座位 → **死人不会插话**
- 唯一例外是 `allowDead: true`，只用于三个死后通道：遗言、开枪、警徽移交
- 测试里有硬断言：`已出局玩家不能"随便发言"（HTTP 400）`

## 五、警长（上警 · 1.5 票 · 发言顺序 · 警徽移交）

第 1 天白天会自动进入**上警环节**：

1. **上警表态**：所有存活玩家依次在公共频道说「我要上警」或「我不上警」，程序自动解析出候选人
2. **警长竞选投票**：**只有没上警的人**能投票（候选人不能投），选出得票最高者当警长（平票则本局无警长）
3. **警长特权**：
   - 放逐投票时**票权 1.5**（计票明细里会标出来，例如 `4号→7号(警长1.5票)`）
   - 可以**决定当天的发言顺序**（控制栏「请警长定发言顺序」→ 警长说「从 3号 开始」→ 队列立刻重排）
4. **警长出局**：无论是被刀、被毒、被票、被枪带走，都会自动登记「待移交警徽」，主持人点一下让警长说「警徽给 X号」或「撕警徽」，警徽就转移或作废

警长可以在 ⚙ 对局设置里整体关闭（关闭后第 1 天不再有上警环节）。

## 六、频道是房子，座位是住客

- 5 个频道在程序**首次启动时创建一次**，整个生命周期内一直存在；`ensureChannels()` 只补缺失的，**永不重建、永不自动清空**。
- 座位只保存一个 `agentId`。右侧面板下拉换模型 = 改这一个字段。测试断言：

  ```
  换模型后频道数量与 id 完全不变（没有重建）
  换模型后每个频道的历史条数完全不变（没有清空）
  换模型后频道里的老消息还在
  新接入的 AI 读得到该座位有权限的全部历史（无缝续玩）
  ```

- 只有「开新一局时勾选清空频道历史」才会清消息——**频道本身依旧保留**（id 不变、数量不变）。
- 删除 AI 成员时，座位只解绑，不删除。

### 2. 身份配比 / 玩家数量

「开新一局」里选板子或手动填（4~18 人）；默认值在 `lib/game.js` 的 `DEFAULT_ROLE_PLAN`（12 人标准局）与 `ROLE_PRESETS`（内置板子）。

### 3. 代码里的常量

```js
// lib/channels.js
export const TUNING = {
  contextLimit: 60,          // 每频道带入的历史条数上限
  maxCharsPerMessage: 500,   // 单条历史消息截断长度
  leakCheckMinLength: 6,     // 泄漏自检的最小比对长度
  leakCheckProbeLength: 40,  // 泄漏自检取样长度
};
```

- `lib/game.js`：`AVATARS` / `COLORS`（座位头像配色）、每天首发轮换、狼刀多数决规则
- `lib/openai.js`：`PRESETS`（厂商预设）、请求超时 180 秒

### 4. 每个 AI 单独可调

「AI 成员库 → 编辑」里可以给**每个模型**单独设温度、最大输出 tokens、人设提示词——
比如给狼配"擅长伪装"的人设，给预言家配"逻辑严密"的人设。

## 十、开发过程中发现并修掉的问题

| 问题 | 性质 | 修复 |
| --- | --- | --- |
| **出局玩家完全没有"遗言"这个环节**（死者说完最后一句就消失），警长也没有 | 规则缺失 | 补上遗言队列 + 警长竞选/特权/警徽移交，并把白天改成状态机推进 |
| 上警结束后又回到上警环节（`needCampaign` 没判断"已产生候选人"） | 流程死循环 | 加上候选人判断，上警 → 投票 → 发言 |
| 观众视角下公共频道消息的 `meta.includedChannels` 会暴露"这人看得到狼人频道"→ 可推断谁是狼 | **真实信息泄漏** | 观众视角剥离 `includedChannels` / `role` 等字段，并加断言 |
| 预言家/女巫的决定解析会读到**上一夜**的发言（第二夜把第一夜的"不用毒药"当成今晚决定） | 跨轮次串味 | 增加 `markers.seerFrom / witchFrom / guardFrom` 游标，只解析本轮 |
| 猎人/狼王是"死后开枪"，但发言校验拦住了已出局玩家 | 功能不可用 | `speakOnce({ allowDead: true })` 专供遗言/开枪/警徽三个死后通道 |
| 守卫"不能连守同一人"只写在提示词里，没有真正拦 | 规则未生效 | `resolveGuard()` 程序侧拦截，越规的守护会被跳过 |
| 女巫"同一晚只能用一瓶药"只写在提示词里 | 规则未生效 | 解析层强制只保留一瓶（解药优先）并回执说明 |
| `[hidden]` 被 `display:inline-flex` 覆盖，"停止"按钮一直显示 | CSS bug | 全局 `[hidden] { display: none !important; }` |
| 控制栏"开局"按钮组无条件显示，白天也出现"天黑请闭眼" | UI 逻辑 bug | 按阶段 gate 显示 |

> "狼人频道"就被带偏了 —— 这反过来印证：**判断隔离不能用全文搜频道名**，正式代码用的是精确行前缀 `[频道名]`。

## 十二、网络代理（访问 Gemini / OpenAI 必需，很多人会踩的坑）

**现象**：`测试连接` / `获取模型列表` 报
`连接超时，网络不通或接口响应太慢（Connect Timeout Error (attempted addresses: 2001:4860:...:443, 172.217.113.4:443 ... timeout: 10000ms)）`
—— 明明浏览器能打开 Google，程序却连不上。

**原因**：**Node.js 的 fetch 不会使用 Windows 的「系统代理」设置**。Clash / v2rayN 这类客户端的默认模式只改系统代理，
浏览器遵守，Node 直接裸连目标 IP（上面日志里那些 `172.217.x.x` 就是 Google 的真实 IP）→ 被墙 → 超时。
（顺带一提：Node 直到 v24 才支持 `HTTPS_PROXY` 环境变量，本程序内置的是 v22，所以环境变量也没用。）

**两种解法（任选其一）**：

1. **点「⚙ 对局设置 → 🔍 自动检测」**（推荐）—— 程序会扫一遍本机常见代理端口，
   用真实请求验证哪个能用（并区分"能上 Google"还是"只能连国内"），检测到就直接启用，不用你记端口
2. **手动填端口**：常见默认值是
   - **Clash Verge / Verge Rev → `7897`**（注意：不是 7890！新版默认端口变了）
   - Clash for Windows / 旧版 Mihomo → `7890`
   - v2rayN → `10809`（HTTP 端口，不是 socks 的 10808）
   - Surge → `6152`

   只支持 http(s) 代理，填 `socks5://…` 会被直接拒绝并提示改用 HTTP 端口。
   或者把代理客户端切成 **TUN / 虚拟网卡（全局路由）模式**，所有进程都走隧道，这里就不用填了。

> 报 `connect ECONNREFUSED 127.0.0.1:7890` 就是这个原因：端口填错了，那个端口上没人监听。
> 报 `连接超时 ... 172.217.x.x:443` 则说明**端口没配或请求根本没走代理**。
> 两种报错含义不同，程序都会说清楚。

填好后可以点 AI 表单里的「测试连接」验证；`/api/state` 里也会回传 `proxy` / `proxyActive` 供界面显示。

> 实现细节：程序内置了一份 undici（约 1.2 MB，编译进 exe），用它的 `ProxyAgent` 给 `fetch` 挂上 `dispatcher`；
> 不配代理时就是普通直连，零额外开销。

## 十三、数据放在哪 / 怎么保证不丢

**所有东西（AI 成员 + API Key + 频道历史 + 对局状态）都在一个文件里：**

```
%LOCALAPPDATA%\AIWerewolf\data\db.json          ← 主数据文件
%LOCALAPPDATA%\AIWerewolf\data\db.json.prev     ← 上一次保存前的版本（自动）
%LOCALAPPDATA%\AIWerewolf\data\backup\2026-10-12.json   ← 每日备份，保留最近 7 天（自动）
```

- **换版本 / 重新打包 exe 都不会动这个目录**，成员和 Key 一直在
- 程序**每次保存**都会更新 `db.json.prev`，并按天写一份备份（同一天覆盖当天的、历史天数保留）
- 界面里可以自助：

| 入口 | 位置 | 作用 |
| --- | --- | --- |
| 📤 导出成员 | AI 成员库左下 | 弹出一段 JSON（含 API Key），复制保存成文件，换电脑/重装时用 |
| 📥 导入成员 | AI 成员库左下 | 粘贴之前导出的 JSON；同名+同地址覆盖更新，其余新增 |
| 🕘 历史备份 | AI 成员库左下 | 列出「上一次保存前」和最近 7 天的每日备份，一键把成员库恢复回来 |

> ⚠️ 唯一会丢数据的情况是**有人手动删掉 `db.json`**（比如清理数据/换机没迁移）。
> 所以加完成员后建议点一次「导出成员」把 JSON 存到网盘或笔记里，这是最稳的一层保险。

## 十四、常见问题

- **AI 不发言 / 频道里出现红字提示**：座位没绑定 AI，或绑定的 AI 被停用；右侧下拉框选一个即可。
- **报「消息隔离告警」**：第二道防线拦下来了，正常设计下不该出现；请把日志里的泄漏来源发出来。
- **狼人讨论完没解析出目标**：程序按多数决解析「刀 X号」，解析不到会随机指定一个存活好人并提示；也可以直接手打。
- **想复盘**：`%LOCALAPPDATA%\AIWerewolf\data\db.json` 保存了全部频道记录。
- **端口冲突**：默认 8789，可用环境变量 `WEREWOLF_PORT` 指定。
- **连不上 Gemini / OpenAI（连接超时）**：见第十二节，Node 不走系统代理，需要在设置里填代理，或把 VPN 换成 TUN 模式。
- **成员没了 / 想换电脑**：见第十三节。程序自带每日备份和「导出成员」，一键就能恢复。
- **服务商下拉里没有我要的厂商**：选「自定义（任意兼容接口）」，把 Base URL 和模型名填进去即可；预设里已有 39 家（国内直连 / 聚合平台 / 海外需代理 / 本地部署 四组）。
- **报 `invalid temperature: only 1 is allowed for this model`**：不是 Key 的问题，是这个模型对参数有硬性要求（Kimi K2 系列、OpenAI o1/o3/o4、gpt-5 等推理模型只允许 `temperature=1`）。
  程序会**自动改用 temperature=1 重试并记住**，测试连接会提示「已自动适配」，你不用改设置。
  如果连去掉 temperature 都被拒绝，说明是别的参数问题，报错里会写清楚。
- **模型名写错**：会返回 `model not found` / `does not exist` 之类，点「获取模型列表」从里面挑即可。

### 报错对照表（程序会把服务商英文错误翻成中文，这里是对照）

| 程序里的提示 | 服务商原话举例 | 到底哪里错了 |
| --- | --- | --- |
| 连接超时：网络不通或接口响应太慢…**（172.217.x.x:443）** | — | **请求没出去**：没配代理，或代理端口填错。见第十二节 |
| 代理 http://127.0.0.1:xxxx 连不上（connect **ECONNREFUSED**） | — | 代理端口填错了（那个端口上没人监听）。用「🔍 自动检测」 |
| **API Key 不正确** | `Incorrect API key provided`（xAI / OpenAI） | Key 本身不对：复制不完整、已被删除、或不是这家平台的 Key |
| **没有带上 API Key** | `No credentials presented.`（xAI） | API Key 输入框是空的（编辑时留空表示沿用已保存的 Key） |
| **账户余额 / 额度不足** | `Insufficient Balance` / `quota exceeded` | 去服务商后台充值 |
| **这个模型对「温度」有硬性要求** | `invalid temperature: only 1 is allowed` | 无害：程序会自动改用 temperature=1 重试 |
| **模型名不存在** | `model not found` / `does not exist` | 模型名拼错，或该账号没开通这个模型 |
| **上下文超出模型长度限制** | `maximum context length` | 把「上下文条数」调小（默认 60） |
| **这个服务商不支持「获取模型列表」** | HTTP 404 | 直接在「模型名」框手输模型名 |

- **同一个 AI 阵营总是很弱**：把「温度」调高一点、或在成员的人设里写得更具体（例如「你是个老练的狼人，擅长悍跳预言家」）。
